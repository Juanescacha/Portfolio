## About the project

This repository contains the source code for my current professional portfolio.

The project is built as a **static Astro site** with English as the default language and a Spanish version under `/es/`. Content is separated from presentation through typed data files, making professional information such as experience, projects, certifications, articles, and social profiles easier to maintain.

Beyond presenting my work, the site is also designed around modern web quality practices: performance, accessibility, internationalization, semantic HTML, structured data, technical SEO, and machine-readable content for search engines and AI systems.

### Main sections

- About
- Work experience
- Selected projects
- Certifications
- Technical articles
- Resume
- Social and professional profiles

## Internationalization

The portfolio supports two languages:

| Language | Route |
| --- | --- |
| English | `/` |
| Spanish | `/es/` |

English is the default locale, while Spanish uses a prefixed route.

The language architecture is configured directly through Astro i18n and keeps localized content separated so that both versions can evolve independently without duplicating the application structure.

## SEO, GEO and AEO

The portfolio includes a technical discoverability layer designed for traditional search engines, answer engines, and AI-assisted discovery.

### Search engine optimization

- Semantic HTML
- Canonical URLs
- Localized metadata
- `hreflang` support
- Open Graph metadata
- Social sharing metadata
- Custom `404` page
- `robots.txt`
- `sitemap.xml`
- Search-friendly static rendering
- Crawlable content without requiring client-side JavaScript

### Structured data

The site includes localized **JSON-LD structured data** based on Schema.org.

The graph models entities such as:

- `Person`
- `WebSite`
- `ProfilePage`
- `Organization`
- `CollegeOrUniversity`
- `EducationalOccupationalCredential`
- `ImageObject`

English and Spanish use separate structured-data files while sharing stable entity identifiers, allowing search engines and other consumers to understand that both localized pages describe the same person and website.

### AI and answer-engine discoverability

The project also exposes:

- `llms.txt` — concise machine-readable portfolio index
- `llms-full.txt` — extended professional context for LLMs and AI agents

These files provide structured context around my professional identity, experience, technologies, projects, certifications, technical focus areas, and authoritative public profiles.

> `llms.txt` complements the site's HTML and structured data. It is not used as a replacement for standard SEO, Schema.org markup, or the sitemap.

## Performance and architecture

The portfolio uses Astro's static output to keep the shipped client-side JavaScript small and preserve fast initial rendering.

Key architectural decisions include:

- Static-site generation
- Component-based Astro UI
- React only where interactivity is useful
- Local variable font loading
- Optimized image handling
- Content separated into typed data modules
- Reusable section components
- Locale-specific content
- Minimal runtime requirements
- Deployment through a CDN-backed platform

The goal is to keep the site simple to maintain while preserving strong performance and a good user experience across devices.

## Content model

Professional content is stored separately from the UI.

- Profile and biography
- Work experience
- Projects
- Certifications
- Technical articles
- Section labels
- Social profiles
- Interface copy

This allows the landing page components to remain focused on rendering while the content can be updated without rewriting presentation logic.

## Local development

### Requirements

- Node.js `>= 22.12.0`
- pnpm

### Install dependencies

```bash
pnpm install
```

### Start the development server

```bash
pnpm dev
```

Astro will start the local development server, typically at:

```text
http://localhost:4321
```

### Build for production

```bash
pnpm build
```

The static production build is generated in:

```text
dist/
```

### Preview the production build

```bash
pnpm preview
```

## Deployment

The site is configured for static output and deployed with Vercel.

A typical deployment flow is:

```text
GitHub
   ↓
Vercel
   ↓
Astro build
   ↓
Static production output
   ↓
juanescacha.dev
```

Because the site is statically generated, most content can be served directly from the CDN without requiring an application server at runtime.
